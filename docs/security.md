# Security and privacy

- Owner routes require a valid server-backed session, a verified email and current membership. Resource selectors and export filters are scoped to that organization. Session cookies are HttpOnly and SameSite Lax, with Secure required in production. Public enrollment is disabled. The operator provisions the initial owner and sends separate verification and password links. Owners can enable TOTP and revoke other sessions.
- The reverse proxy must overwrite the trusted client-IP header from the actual connection and the application port must be private. Auth rate limits use PostgreSQL. API mutations require the exact configured origin. Production uses same-origin requests, HTTPS, security headers, and private, uncached API responses. Invalid or inaccessible resource IDs receive generic responses. Log denied requests and watch for repeated access attempts.
- Runtime roles differ from the database migration owner. Only operators can run cross-organization jobs, manage sender secrets, or work with full backups. Database credentials, Meta tokens, SMTP credentials, and backup keys belong in secret stores with role-specific access. Never share backup credentials with the API or worker. Use separate projects, keys and data in staging and production.
- Tenant details should be limited to contact, rental and consent records. Agree with the operating business on purposes, notices, retention and deletion procedures before collecting real data. Review Indian privacy requirements and the effective dates with the operator's privacy adviser. Document each consent source and clear it when a WhatsApp contact changes. When a deletion request involves retained financial or backup records, apply the agreed retention rules and avoid reinstating deleted or opted-out contacts during recovery. [India Ministry of Electronics and IT data protection resources](https://www.meity.gov.in/data-protection-framework)
- Operator logs should capture failed auth and denied accesses without credentials, receipt bodies, raw webhooks, or phone numbers. Set restricted access and retention for logs, mail, queue records and exports. Have the on-call operator investigate repeated authorization denials, mismatched receipt states, and failed or overdue backup runs. [OWASP multi-tenant security](https://cheatsheetseries.owasp.org/cheatsheets/Multi_Tenant_Security_Cheat_Sheet.html)
